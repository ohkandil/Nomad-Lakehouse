# Nomad Lakehouse — Agent Instructions

## Repository Purpose

Local-first data lakehouse for Ubuntu servers and homelabs, implementing Bronze/Silver/Gold medallion workflows on MinIO + PostgreSQL + DuckDB, with an Apache Iceberg-ready architecture. Designed as a portfolio project demonstrating data engineering maturity (CI, type safety, security scanning, documentation discipline).

## Key Directories

| Directory | Purpose |
|---|---|
| `scripts/` | Pipeline Python scripts (`create_bronze_tables.py`, `bronze_to_silver.py`, `silver_to_gold.py`) and shell ops scripts (setup, health, security, systemd) |
| `dashboard/` | FastAPI admin dashboard — `app.py` (router), `health_sources.py`, `pipeline_sources.py`, `security_sources.py`, `models.py`, Jinja2 templates, static JS/CSS |
| `tui/` | TypeScript setup wizard (`src/App.tsx`, `src/index.tsx`) built on `@opentui/core` |
| `tests/` | Unit tests; `conftest.py` adds repo root to `sys.path` |
| `configs/` | Caddy reverse-proxy template and systemd service templates |
| `data/contracts/` | JSON schema contracts (e.g., `bronze_orders_contract.json`) |
| `data/sample/` | Source CSVs (e.g., `orders.csv`) |
| `data/output/` | DuckDB files and pipeline CSV outputs (gitignored) |
| `docs/` | Setup, deployment, architecture, admin dashboard docs, week closure evidence |

## Commands

### Lint & Format
```bash
ruff check .
```

### Type Checking
```bash
mypy scripts
```

### Tests
```bash
python3 -m pytest              # runs all tests under tests/
python3 -m pytest tests/test_bronze_setup.py -v   # focused
```

### Security Scanning
```bash
sudo ./scripts/security_scan.sh
python3 -m pip_audit --skip-editable --ignore-vuln CVE-2026-3219
python3 -m bandit -r scripts
```

### Dashboard
```bash
python3 -m uvicorn dashboard.app:app --host 127.0.0.1 --port 8088
```

### Pipeline (requires MinIO + PostgreSQL running via `docker-compose up`)
```bash
python3 scripts/create_bronze_tables.py
python3 scripts/bronze_to_silver.py
python3 scripts/silver_to_gold.py
```

### Install Dependencies
```bash
pip install -e .[dev,lakehouse]
# or via script:
INSTALL_PROFILE=dev ./scripts/setup_python_env.sh
```

## Architecture & Conventions

- **Python 3.11+** required. `pyproject.toml` is the single source of dependency truth.
- **Ruff** config: line-length 100, target py311, rules E/F/I/UP/B/SIM/RUF.
- **Mypy** strict mode enabled for `scripts/`.
- **All Python pipeline scripts** live in `scripts/` and use `from __future__ import annotations`. They import from each other via `importlib` or direct imports with repo root on `PYTHONPATH`.
- **Dashboard** is a standalone FastAPI app in `dashboard/`. Data collection is split into `*_sources.py` modules; templates use Jinja2.
- **Shell scripts** target Ubuntu/Linux; CI runs on `ubuntu-latest`.
- **`tests/conftest.py`** injects the repo root into `sys.path` — mirror this if writing new test files outside `tests/`.
- **Data contracts** are versioned JSON files in `data/contracts/` — generated by pipeline scripts, consumed by downstream validation.
- **Environment variables** are loaded from `.env` (gitignored). See `.env.example` for all required vars. Never commit secrets.
- **Docker Compose** orchestrates MinIO, PostgreSQL, and an init container. A `duckdb` tools profile is available for ad-hoc queries.

## CI Pipeline (`.github/workflows/ci.yml`)

Runs on push/PR: ruff → mypy scripts → pytest → bronze smoke test (Postgres service container) → pip-audit → bandit. The smoke test verifies `bronze.orders` is non-empty in DuckDB.

## Coding Rules

1. **Documentation policy**: every behavioral/operational/workflow change must include matching docs updates in the same PR.
2. **Test policy**: every implementation change must include matching test coverage updates.
3. **Import style**: absolute imports with repo-root path; `from __future__ import annotations` at top of every `.py` file.
4. **Logging**: use `structlog` (listed as a dependency) — no raw `print()` in production scripts.
5. **Validation**: use Pydantic models for data validation (see `BronzeOrder`, `JdbcTarget` in `create_bronze_tables.py`).

## Gotchas

- Shell scripts use `sudo` and expect Linux; they won't work directly on Windows (this is Linux-first by design).
- `data/output/` is gitignored — it contains runtime artifacts (`lakehouse.duckdb`, CSV exports). Create with `mkdir -p data/output` if missing.
- `pip-audit` has a known CVE ignore (`CVE-2026-3219`) — maintain this if updating dependencies.
- The `duckdb` Docker service uses a `tools` profile: `docker compose --profile tools up -d` to access it.
- `scripts/__init__.py` exists so `scripts/` is a Python package, enabling cross-script imports.
